OpenCode

Un deuxième agent, les mêmes règles.

OpenCode est un agent de code open source qui tourne dans le terminal, comme Claude Code. Dans le harness, c'est le deuxième avis : il travaille avec d'autres modèles, mais suit exactement la même méthode.

Pourquoi deux agents

Un avis qui vient d'ailleurs.

Un modèle relit mal ses propres angles morts. Le skill revue confie la relecture à un autre modèle quand c'est possible, et toujours quand le changement touche à l'argent, aux droits d'accès, aux données personnelles ou à la base.

Claude Code

L'agent principal

Il lit ~/.claude/CLAUDE.md, les skills de ~/.claude/skills/ et, dans un projet, le CLAUDE.md qui importe AGENTS.md.

OpenCode

Le deuxième avis

Il lit ~/.config/opencode/AGENTS.md, les mêmes skills, et directement le AGENTS.md du projet. Le fournisseur de modèles dépend de votre configuration OpenCode.

Une session de travail

Reprendre un projet ou relire un ticket

Reprendre l’entretien

Ouvrez OpenCode depuis le dossier du projet. Dites "reprends" pour que l’agent lise la passation et les notes utiles. Dites "cadrage" pour continuer l’entretien et compléter la phase en cours dans Obsidian.

Demander un deuxième avis

Donnez le ticket et la demande de fusion, puis demandez une revue. OpenCode lit les critères du ticket et les règles du projet, relève les écarts et cite les fichiers concernés. Vous pouvez ensuite demander un contrôle ciblé.

Où il lit

Quatre portes d'entrée.

L'installeur branche les trois premières. Les fichiers du projet viennent du gabarit ou du ticket socle, selon le parcours choisi.

Ce qu'il litOùD'où ça vient
Les règles communes~/.config/opencode/AGENTS.mdLien vers les règles générées : le moteur, puis votre profil
Les skills~/.claude/skills/<nom>/SKILL.mdOpenCode lit ce dossier, prévu pour Claude Code. Sans Claude Code sur la machine, l'installeur passe par ~/.config/opencode/skills/
Les règles du projetAGENTS.md du projetLe gabarit, rempli par le skill cadrage
Les outils MCPopencode.json du projetCopié par nouveau-projet

Les règles générales viennent du fichier global. Les consignes propres au logiciel viennent de son AGENTS.md. Ouvrir la session dans le bon dossier donne à OpenCode accès aux instructions qui s’appliquent. Le recours à CLAUDE.md dépend de la version et de la configuration.

Les outils MCP

Sept outils, trois allumés.

Un MCP est un serveur qui donne des outils en plus à un agent, par exemple lire la documentation d'une bibliothèque ou piloter un navigateur. Chaque outil prend un peu de place dans la mémoire de travail de l'agent.

allumer un outil

Passer enabled à true

Dans opencode.json du projet, mettez "enabled": true sur l'outil, puis rouvrez le projet. Claude Code, lui, charge un fichier à part avec --mcp-config.

deux formats

Même liste, écriture différente

OpenCode lit la clé mcp et les variables {env:NOM}. Claude Code lit mcpServers et ${NOM}. Une clé ne s'écrit jamais : seulement le nom de sa variable.

Le faire marcher

La liste de contrôle.

  1. Le dossier d'OpenCode existe avant l'installeur

    Sans ~/.config/opencode, l'installeur écrit "[ignoré] OpenCode n'est pas installé ici" et ne branche pas les règles. Lancez OpenCode une fois ou créez le dossier, puis relancez l'installeur.

  2. Le vérificateur dit OK pour OpenCode

    Sa rubrique "Règles pour OpenCode" contrôle que le lien vers les règles générées est à jour.

  3. Aucun skill en double

    Un même nom dans ~/.claude/skills et dans ~/.config/opencode/skills apparaît deux fois dans OpenCode. Le vérificateur le signale.

  4. La lecture du dossier .claude reste active

    D'après la documentation d'OpenCode, la variable OPENCODE_DISABLE_CLAUDE_CODE=1 coupe toute lecture de .claude. Avec elle, les skills du harness disparaissent.

  5. Une session neuve et les deux mots

    Après chaque installation ou changement de règles, fermez OpenCode, rouvrez-le, puis demandez les mots de contrôle : copeau-42 et rabot-17.

Agnostique, par principe

Rien qui ne marche que pour un.

  • Un SKILL.md n'a que deux champs d'en-tête : name et description. Un champ propre à un seul agent casserait l'autre.
  • Pas de plugin d'agent, même pratique : un seul des deux le lirait.
  • GitHub passe par la commande gh, que les deux agents savent lancer, plutôt que par un serveur MCP.
  • Chaque outil MCP est écrit deux fois, une par format, avec la même version épinglée.
