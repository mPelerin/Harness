Hermès

Il répartit, surveille et prévient.

Hermès tourne sur votre serveur. Il reçoit un lot de travail, le découpe et confie chaque ticket à un agent spécialisé. Lui ne code jamais. Le matin, vous trouvez une préprod à tester et un message qui dit ce qui est fait.

Ce qu'est Hermès

Un agent, des profils, un tableau.

Hermes Agent est un agent open source de Nous Research. Le harness s'en sert pour trois de ses fonctions.

les profils

Un agent par métier

Chaque profil a son dossier, son modèle et un fichier SOUL.md qui décrit son rôle : écrans, données, sécurité, déploiement, débogage.

le kanban

Une carte par tâche

Un tableau partagé par tous les profils. Une carte porte une tâche, son profil, ses dépendances et son état : en cours, finie ou bloquée.

les messages

Un mot sur Telegram

Hermès envoie le résumé du matin. Il part toujours, même quand tout a échoué.

0ligne de code écrite par l'orchestrateur
4verbes : découper, répartir, surveiller, alerter
1carte kanban par ticket
1seul profil reçoit les secrets de déploiement
Le mode nuit

Vous cadrez le soir, vous testez le matin.

Le skill nuit n'invente aucune méthode. Il enchaîne tickets, feature, livrer et preprod, en confiant chaque geste technique à une carte.

  1. Le soir

    Vous dites "oui" au mode nuit

    Le cadrage est poussé sur preprod. Le pré-vol est vert : aucune variable, aucun compte ni aucune migration ne manque. Sinon, rien ne part.

  2. Sur le PC

    L'agent passe la main, puis s'arrête

    Il dépose la tâche chez Hermès par SSH avec la commande hermes-nuit, donne son numéro, et ne code rien sur le PC.

  3. Sur le serveur

    Les tickets sont créés

    À partir des stories. Les tickets sensibles sont marqués, les prérequis sont écrits par leur nom, jamais par leur valeur.

  4. Répartir

    Une carte par ticket, dans l'ordre des dépendances

    Chaque carte reçoit un profil adapté et le skill feature. Elle code, teste, ouvre la demande de fusion vers preprod et fusionne quand la CI est toute verte.

  5. Surveiller

    Regarder sans intervenir

    Une carte en échec passe "bloquée". Hermès note la raison. Il ne la relance pas à la main et ne code pas à sa place.

  6. Déployer

    Une carte pour la préprod

    Le profil de déploiement applique le skill preprod. Preuve attendue : 401 sans login, 200 avec, et le commit en ligne égal à celui de origin/preprod.

  7. Prévenir

    Le message du matin

    L'adresse de préprod, les tickets fusionnés, ceux laissés de côté avec leur raison. Jamais le mot de passe.

  8. Le matin

    La porte 2, sur la préprod

    Vous testez sur l'adresse, puis "go tout", "go 2 4" ou ce qui ne va pas. Rien ne part vers main : la porte 3 reste la même.

Trois exceptions

Valables pour ce lot et cette nuit.

01

Le "oui" vaut deux "go"

Celui du découpage en tickets, et celui de la fusion dans preprod. Jamais celui de main.

02

La porte 2 se passe le matin

Sur le site de préprod. Les tickets fusionnés restent ouverts jusqu'à votre "go".

03

Un ticket sensible attend

Argent, droits d'accès, données personnelles, base de données, nouvelle bibliothèque : créé, jamais codé sans un "go" écrit.

Choisir le profil

Le bon agent pour chaque carte.

La liste des profils se lit sur le serveur, à chaque nuit. Si votre instance a un fichier profils.md, Hermès le suit en premier : il dit quels profils codent et lesquels sont réservés à autre chose.

Travail dominantRôle à chercher
écran, page, composant, stylefront, interface
schéma, migration, requête, donnéedonnées, base
mot de passe, session, droits d'accèssécurité
CI, conteneur, volume, déploiementplateforme, déploiement
test qui échoue, défaut à reproduiredébogage, test

Un ticket qui mêle deux domaines prend le profil du plus risqué : sécurité, données et déploiement passent avant l'écran.

  1. Le profil existe

    Il figure dans hermes profile list. Hermès ne crée, ne modifie ni ne supprime jamais un profil.

  2. Son rôle est de coder

    Ni recherche, ni messagerie, ni usage personnel.

  3. Son modèle convient au code

    Un profil dont le modèle est réglé sur synthetic ne reçoit pas de carte de code. Aucun profil ne convient : la carte reste bloquée, et le message du matin le dit.

En journée

La délégation, sans bruit.

Quand la clé ORCHESTRATEUR est remplie dans harness.conf, le skill feature ne code plus sur le PC. Il confie chaque ticket à Hermès et ne vous montre qu'un tableau.

déposer

Une sous-conversation par ticket

Elle dépose la demande avec orchestrateur deposer-demande, puis la suit avec orchestrateur suivre. Elle absorbe l'attente et ne répond qu'une fois, à la fin.

rester local

"feature local"

Force le codage sur le PC, sans lire la clé. Utile pour un petit ticket, ou quand le serveur est occupé.

Code de sortieCe qu'il veut dire
0La carte est finie
3ORCHESTRATEUR est vide : pas de délégation
4La carte est bloquée ou archivée
5Délai dépassé, la carte travaille encore
6La demande est finie sans carte de code
Ce qu'Hermès ne fait jamais

Chaque geste technique appartient à une carte.

  • Coder, fusionner ou déployer depuis sa propre tâche d'orchestrateur.
  • Pousser ou fusionner sur main, ou toucher à une adresse de production.
  • Fusionner une demande dont la CI est rouge, absente ou en cours.
  • Fermer un ticket : c'est votre "go" du matin qui le fait.
  • Lire, afficher ou inventer un secret. Seul le profil de déploiement reçoit ceux de Coolify et de la préprod.
  • Créer une préprod sans login, ou plus d'une ressource Coolify par projet.
  • Répondre à une demande d'accord à votre place. Une commande refusée arrête la carte.
Sur le serveur

Ce qui doit être en place.

  1. Hermes Agent

    Avec son tableau kanban, l'envoi Telegram, vos profils, et la commande hermes-nuit qui dépose une tâche chez l'orchestrateur.

  2. Les deux dépôts du harness

    Installés pour l'utilisateur qui fait tourner Hermès, avec harness.conf et profils.md dans ~/.config/harness/. Sans eux, la carte de déploiement s'arrête sur une clé absente.

  3. Le profil de déploiement

    Son nom est dans PROFIL_DEPLOIEMENT. C'est le seul qui reçoit le jeton Coolify et le login de préprod, depuis le coffre de secrets.

  4. Coolify prêt à l'emploi

    Coolify est le programme qui fait tourner vos applis dans des conteneurs. Son API est activée, l'adresse d'appel est autorisée, le jeton a les droits de lecture, d'écriture et de déploiement. Pour un dépôt privé, sa source GitHub est connue par son identifiant, UUID_SOURCE_COOLIFY.
